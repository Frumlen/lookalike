# lookalike для Android

Распознавание целиком на телефоне: камера, модель и база лежат в самом
приложении. Ни сервера, ни интернета не нужно.

## Как собрать

**1. Подготовить модель и базу** (делается на компьютере, из корня проекта):

```bash
.venv/bin/python android/export/export_onnx.py     # DINOv2 -> ONNX, ~331 МБ
.venv/bin/python android/export/quantize.py        # сжатие до int8, ~88 МБ
.venv/bin/python android/export/export_index.py    # index.npz -> assets
```

Файлы лягут в `app/src/main/assets/`. В репозиторий они не попадают —
слишком тяжёлые, каждый собирает у себя.

**2. Собрать apk:**

```bash
cd android
JAVA_HOME=$(brew --prefix openjdk@17) ./gradlew assembleDebug
```

Готовый файл: `app/build/outputs/apk/debug/app-debug.apk`, около 100 МБ.

**3. Поставить на телефон:**

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## Экраны

**Главный** — камера и кнопка «Распознать». Под ней пять ближайших товаров
с процентами. Нажатие на любую строку предлагает **запомнить текущий кадр**
как ещё один снимок этого товара: так система становится точнее прямо в работе.

**Новый товар** — ввести название и отснять несколько кадров подряд.
Обучения нет, товар готов сразу после первого снимка.

**Товары** — список с числом снимков у каждого. Меньше четырёх подсвечивается:
такой товар будет узнаваться неуверенно. Здесь же переименование, удаление
и выгрузка базы наружу.

## Обмен базой между устройствами

Кнопка **«Поделиться базой»** в каталоге собирает всё содержимое в один файл
`lookalike-base-ГГГГ-ММ-ДД.zip`: векторы, названия и снимки. Файл самодостаточный —
не зависит от того, что зашито в конкретную сборку приложения.

Дальше его можно отправить куда угодно — на другой телефон, в сообщение,
на компьютер.

**На другом устройстве:** каталог → «Загрузить базу» → выбрать файл.
Прежняя база заменяется целиком.

**На компьютере:**

```bash
.venv/bin/python android/export/import_from_phone.py ~/Downloads/lookalike-base-2026-09-07.zip
.venv/bin/python build_index.py build
```

Первая команда раскладывает снимки, сделанные телефоном, по папкам
`photos/<название товара>/`. Вторая пересчитывает векторы на общих правилах.
Снимки с телефона сохраняются в размере входа модели (224 px), поэтому
качество при пересчёте не теряется.

Чтобы разослать обновлённую базу на все устройства, соберите новый apk —
или выгрузите файл из одного телефона и загрузите в остальные.

## Где живёт база

При первом запуске база копируется из assets в память приложения и дальше
правится там. Обновления из apk её не затирают — чтобы начать с чистой,
надо стереть данные приложения.

Кнопка «Выгрузить базу» кладёт `index.bin` и `index.json` в
`Android/data/ru.lookalike/files/` — забрать можно проводником или по кабелю,
без всяких разрешений.

## Как устроено

| Файл | Отвечает за |
|---|---|
| `Recognizer.kt` | загрузка модели и базы, кадр → вектор → поиск ближайших |
| `MainActivity.kt` | камера, кнопка, вывод результатов |

Предобработка кадра повторяет ту, что делает `build_index.py` на компьютере:
короткая сторона к 256, центральный квадрат 224×224, нормировка по ImageNet.
Поэтому база, собранная на компьютере, работает в телефоне без переделки.

Поиск ближайших — обычный перебор: 1586 векторов по 768 чисел, около миллиона
умножений. На телефоне это доли миллисекунды, всё время уходит на модель.

## Обновить список товаров

База товаров живёт на компьютере. После правки фотографий:

```bash
.venv/bin/python build_index.py build              # пересобрать index.npz
.venv/bin/python android/export/export_index.py    # переложить в assets
cd android && ./gradlew assembleDebug              # пересобрать apk
```

Модель при этом не меняется — только `index.bin` и `index.json`.

## Требования

- JDK 17 (`brew install openjdk@17`)
- Android SDK, platform 34
- Телефон с Android 8 и выше
