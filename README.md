# lookalike

Поиск похожих товаров по фотографии. Кладёте снимки в папки, строите базу,
загружаете новое фото — получаете список товаров, на которые оно похоже,
с процентом сходства.

Работает **полностью офлайн**: интернет нужен один раз, чтобы скачать модель.

Есть приложение для Android — то же самое целиком на телефоне, см. `android/`.

## Как это устроено

Обучения нет. Готовая модель **DINOv2** превращает картинку в вектор из 768 чисел,
в котором похожие предметы оказываются рядом. Распознавание — поиск ближайших
векторов в базе.

Отсюда главное свойство: **добавить товар = положить папку с фотографиями**.
Никакого переобучения, никакого GPU, никакой разметки.

```
фото  →  DINOv2  →  вектор  →  ближайшие в базе  →  список похожего
```

## Установка

```bash
git clone <адрес репозитория>
cd lookalike
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

При первом запуске скачаются веса модели (~350 МБ) — дальше интернет не нужен.

## Работа

### 1. Разложить фотографии

Одна папка — один товар. **Имя папки становится тем, что покажет система.**

```
photos/
├── Бананы/
│   ├── 1.jpg
│   └── 2.jpg
├── Помидор розовый/
│   └── 1.jpg
└── Птичье молоко/
    ├── 1.jpg
    └── 2.jpg
```

5–8 снимков на товар достаточно. Форматы: jpg, png, webp, bmp.
Кадры мельче 32 пикселей пропускаются.

### 2. Построить базу

```bash
.venv/bin/python build_index.py build
```

Считаются **только новые и изменённые** файлы, остальные берутся из готовой базы.
Первый запуск на 1500 снимках — около 20 минут, дальше секунды.

### 3. Запустить страницу

```bash
.venv/bin/python serve.py 8100
```

Открыть **http://127.0.0.1:8100** и загрузить фотографию — перетаскиванием,
выбором файла или вставкой из буфера.

В ответ пять ближайших товаров: название, процент сходства и **тот эталонный
снимок из базы, на который похоже**. Последнее важнее процента — сразу видно,
почему система так решила.

## Обслуживание

| Задача | Действие |
|---|---|
| Добавить товар | создать папку с фото → `build_index.py build` |
| Добавить снимки | положить файлы в папку → `build_index.py build` |
| Удалить товар | удалить папку → `build_index.py build` |
| Переименовать товар | переименовать папку → `build_index.py build` |
| Исправить ошибку распознавания | удалить сбивающий снимок → `build_index.py build` |
| Посмотреть состав базы | `build_index.py stats` |

Сервер перезапускать не нужно — он подхватывает пересобранную базу сам.

## Настройки

Задаются переменными окружения:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `PHOTOS_DIR` | `photos` | папка с фотографиями |
| `INDEX_FILE` | `index.npz` | файл базы |
| `MODEL_NAME` | `facebook/dinov2-base` | модель-кодировщик |

Модель поменьше и побыстрее — `facebook/dinov2-small`, точнее и медленнее —
`facebook/dinov2-large`. После смены модели базу нужно построить заново:
удалите `index.npz` и запустите `build`.

## Точность

Замер на 1586 снимках, 55 классах товара, методом «убрать кадр и найти его
по остальным»:

| | |
|---|---|
| TOP-1 | **87,3%** |
| TOP-3 | 93,2% |
| TOP-5 | 94,6% |

Это на изображениях из интернета. На снимках, сделанных в реальных условиях
съёмки — при постоянном ракурсе, освещении и фоне — точность заметно выше.

**Ориентиры по проценту сходства:**

| Сходство | Смысл |
|---|---|
| выше 90% | почти наверняка тот же товар |
| 80–90% | тот же вид, другой сорт или ракурс |
| 70–80% | родственная категория |
| ниже 70% | ничего похожего в базе нет |

---

## Что влияет на качество

- **Постоянные условия съёмки важнее числа снимков.** Фиксированная камера,
  один фон и одно освещение дают больше, чем сотни разнородных кадров
- **Пять чистых снимков лучше пятнадцати случайных.** Каждая мусорная картинка
  в базе тянет распознавание к себе
- **Крупный план**, товар занимает бо́льшую часть кадра
- Выкидывать коллажи, картинки с текстом, рисунки и посторонние предметы
- Визуально одинаковые товары модель не различит — и не должна.
  Показывайте оператору несколько вариантов и давайте выбрать
