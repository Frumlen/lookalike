# lookalike

Приложение узнаёт товар по фотографии. Навели камеру — оно показывает,
что это, и насколько уверено.

Работает **полностью офлайн**: интернет не нужен ни при установке, ни в работе.
Всё считается прямо в телефоне.

Главное свойство: **обучать ничего не надо**. Чтобы приложение узнавало новый
товар, достаточно снять его несколько раз. Работать начинает сразу.

---

## Что внутри

Готовая модель переводит снимок в набор чисел — так, что похожие предметы
оказываются рядом. Распознать значит найти в базе ближайшие снимки.

Поэтому добавить товар — это просто дописать в базу несколько его фотографий.
Никакого обучения, ожидания и пересборки.

---

## Как пользоваться

### Узнать товар

Положить товар перед камерой и нажать **«Распознать»**.

Через секунду снизу появятся пять вариантов. Самый вероятный — сверху,
он подсвечен. Рядом с каждым процент: насколько похоже.

Примерные ориентиры:
— больше 90% — почти наверняка он
— 80–90% — тот же товар, но снят иначе
— меньше 70% — такого в базе, скорее всего, нет

### Система ошиблась

Нажать на строку с правильным товаром и подтвердить **«Запомнить»**.

Приложение добавит текущий кадр к этому товару, и в следующий раз узнает его
увереннее. Так его можно доучивать прямо в работе, ничего не пересобирая.

### Добавить новый товар

1. Положить товар перед камерой
2. **«Новый товар»** → написать название → **«Начать»**
3. Нажимать **«Снять»**, каждый раз меняя ракурс или количество
4. Когда хватит — **«Готово»**

Сколько снимков нужно:
— похожие друг на друга, вроде конфет в пакетиках — до 30
— обычные: яблоки, помидоры, картошка — 10–15
— редкие, ни на что не похожие — 5

Правило простое: чем больше у товара двойников, тем больше кадров.

### Посмотреть, что приложение запомнило

**«Товары»** — список всего, что оно знает, и сколько снимков у каждого.
Оранжевая цифра означает, что снимков мало и товар будет узнаваться плохо.

Нажать на товар — видны все его снимки.

### Убрать неудачный снимок

Открыть товар и нажать на снимок. Смазанные кадры и случайно попавший
чужой товар сбивают распознавание, их стоит удалять.

### Переименовать товар

Открыть товар и нажать **«Переименовать»** внизу. Название сразу поменяется
и в результатах распознавания.

Удалить товар целиком — удержать его в списке.

### Передать базу на другой телефон

**«Товары»** → **«Поделиться базой»**. Приложение соберёт всё в один файл
и предложит отправить: в Telegram, на почту, куда угодно.

На другом телефоне: **«Товары»** → **«Загрузить базу»** → выбрать файл.
Прежняя база заменится целиком.

### Получить вес с весов

**«Весы»** → вписать IP-адрес и порт весов → **«Получить вес»**.

Адрес смотрите в настройках самих весов — те же, что прописаны в 1С.
Работает с весами Масса-К по «Протоколу 100» (Ethernet).

Кнопка «Запросить параметры весов» покажет модель, пределы взвешивания
и цену деления — годится, чтобы убедиться, что связь есть.

### Отдать данные в 1С

**«Для 1С»** → **«Запустить»**. Приложение начинает работать как устройство
в сети: 1С сама забирает у него вес и штрихкод распознанного товара.

На экране показан адрес, который вписывают в 1С. Подробно — `docs/1С_ИНТЕГРАЦИЯ.md`.

### Начать базу с нуля

**«Товары»** → **«Очистить базу»** внизу. Приложение переспросит дважды:
вернуть удалённое нельзя.

## Установка на телефон

1. Скачать `lookalike.apk`
2. Открыть файл на телефоне
3. Разрешить установку, когда телефон спросит
4. При первом запуске разрешить доступ к камере

Нужен Android 8 или новее. Файл занимает около 120 МБ — почти всё это модель
распознавания, она лежит внутри и потому не нужен интернет.

## Для разработчика

Кроме приложения есть та же система на компьютере: там собирается база,
которая потом попадает в телефон.

### Как разложены фотографии

Одна папка — один товар. **Имя папки становится тем, что покажет система.**

```
photos/
├── Бананы/
│   ├── 1.jpg
│   └── 2.jpg
└── Помидор розовый/
    └── 1.jpg
```

### Собрать базу

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python build_index.py build
```

Считаются только новые и изменённые файлы. Первый запуск на полутора тысячах
снимков занимает минуты, дальше секунды.

### Посмотреть в браузере

```bash
.venv/bin/python serve.py 8100
```

Открыть http://127.0.0.1:8100 и загрузить фотографию.

### Собрать приложение

См. `android/README.md`.

### Обслуживание базы

| Задача | Действие |
|---|---|
| Добавить товар | создать папку с фото → `build_index.py build` |
| Удалить товар | удалить папку → `build_index.py build` |
| Убрать плохой снимок | удалить файл → `build_index.py build` |
| Посмотреть состав | `build_index.py stats` |

Сервер перезапускать не нужно, он подхватывает пересобранную базу сам.

### Настройки

Задаются переменными окружения: `PHOTOS_DIR` (папка с фото, по умолчанию
`photos`), `INDEX_FILE` (файл базы, `index.npz`), `MODEL_NAME` (модель,
`facebook/dinov2-small`).

После смены модели базу нужно собрать заново: удалить `index.npz` и запустить
`build`.

## Точность

Замер на 1586 снимках, 55 классах товара:

— верный ответ первым: **87%**
— верный ответ среди трёх показанных: **93%**
— среди пяти: **95%**

Это на картинках из интернета. На снимках, сделанных в одних и тех же условиях —
та же камера, то же освещение, тот же фон — точность заметно выше.

Что помогает больше всего:
— постоянные условия съёмки важнее числа снимков
— пять чистых кадров лучше пятнадцати случайных
— товар должен занимать бо́льшую часть кадра
— визуально одинаковые товары модель не различит и не должна: показывайте
  оператору несколько вариантов и давайте выбрать
