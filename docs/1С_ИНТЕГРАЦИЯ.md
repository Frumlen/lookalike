# Связь с 1С:Розница

Приложение работает как весы нового поколения: **отдаёт вес и штрихкод
распознанного товара**. Ничего никуда толкать не нужно — 1С сама забирает
данные, когда они ей понадобятся.

---

## Как называть товар и куда вводить штрихкод

Это главное, от чего зависит, найдёт ли касса позицию.

**Название — для человека.** Его видит продавец на экране после распознавания.
Пишите так, как товар называется в 1С: проще сверять и объяснять.

**Номер на весах (PLU) — для кассы.** Отдельное поле в карточке товара.
Именно из него собирается штрихкод, по которому 1С находит номенклатуру.

Раньше номер вытаскивался из названия папки — так делать нельзя:
переименовали товар, и связь с кассой молча оборвалась. Теперь это
независимые поля.

### Где взять номер

Тот же, что у товара в 1С. Смотрится в карточке номенклатуры или в выгрузке
товаров на весы: там у каждого весового товара есть свой номер, обычно
от 1 до 99999.

### Где ввести

**При создании:** «Новый товар» → поля «Название», «Номер на весах»,
«Штрихкод».

**Потом:** «Товары» → выбрать товар → «Переименовать» внизу. Там же меняются
номер и штрихкод.

Товар без номера виден сразу: и на главном экране, и в карточке пишется
«без номера — касса не найдёт».

### Поле «Штрихкод»

Нужно только для **штучного** товара, у которого есть собственный EAN-13.
Для весового заполнять не надо: штрихкод собирается из номера и массы
на лету, при каждом запросе.

---

## Что отдаёт приложение

```
http://АДРЕС:8090/
```

```json
{
  "weight_g": 1234,
  "stable": true,
  "name": "Курзе с мясом (хадум)",
  "plu": "55",
  "barcode": "",
  "weight_barcode": "2000550012346",
  "score": 0.93,
  "age_ms": 1500
}
```

| Поле | Что это |
|---|---|
| `weight_g` | масса в граммах; `null` — вес ещё не запрашивали |
| `stable` | масса устоялась. Пока `false`, значение брать не стоит |
| `name` | название для человека |
| `plu` | номер товара на весах |
| `barcode` | собственный штрихкод, если задан (штучный товар) |
| `weight_barcode` | **готовый весовой штрихкод**: номер плюс текущая масса |
| `score` | насколько уверено распознавание, 0–1 |
| `age_ms` | сколько прошло с последнего обновления |

Ещё два адреса, если нужно что-то одно: `/weight` и `/product`.

## Шаблон весового штрихкода — должен совпадать

`weight_barcode` собирается по той же разметке, что настроена в 1С.
**Если они разойдутся, касса прочитает не тот товар или не прочитает вовсе.**

В 1С: Администрирование → Подключаемое оборудование → **Шаблоны весового
штрихкода**. Обычный вид — `2ККККК ВВВВВВ К`: префикс, номер товара,
масса в граммах, контрольная цифра.

В приложении: «Для 1С» → раздел **«Весовой штрихкод»**. Три поля — префикс,
сколько цифр под номер, сколько под массу. Под ними приложение показывает
получившийся шаблон и живой пример:

```
Шаблон: 2ККККК ВВВВВВ К
Пример (номер 55, масса 1234 г):
2000550012346
```

Если разрядность не даёт 12 цифр до контрольной, приложение честно скажет,
что штрихкод собран не будет, и назовёт текущую длину. Молча отдавать
неверный код — хуже, чем не отдать ничего.

## Что будет, если товара нет в базе 1С

Касса скажет «штрихкод не найден» или «товар не зарегистрирован» и не даст
добавить позицию в чек. Ничего не сломается, но продать не получится.

Причины по убыванию частоты:

**Номер на весах не совпадает с 1С.** Самое частое. Проверьте номер
в карточке товара в приложении и в номенклатуре 1С.

**Шаблон штрихкода разошёлся.** Сравните шаблон в приложении и в 1С.

**Товара нет в 1С вовсе.** Приложение может знать товар, которого нет
в номенклатуре — оно узнаёт по фотографии, а не по справочнику. Тогда
позицию надо сначала завести в 1С.

**Номер не задан.** Тогда `weight_barcode` придёт пустым. На экране такой
товар помечен «без номера — касса не найдёт».

Не ошибётся ли распознавание — вопрос отдельный. Продавец видит пять
вариантов и выбирает нужный, а выбранный сразу уходит в 1С. Ошибка модели
исправляется одним нажатием.

## Настройка в 1С

Два способа. Работают одновременно и не мешают друг другу.

### Способ 1: вес и штрихкод вместе

Один запрос — оба значения. Драйвер не нужен, только обычный HTTP.

```bsl
Функция ПолучитьДанныеСУстройства()

    Соединение = Новый HTTPСоединение("192.168.1.114", 8090, , , , 5);
    Ответ = Соединение.Получить(Новый HTTPЗапрос("/"));

    Если Ответ.КодСостояния <> 200 Тогда
        Возврат Неопределено;
    КонецЕсли;

    Чтение = Новый ЧтениеJSON;
    Чтение.УстановитьСтроку(Ответ.ПолучитьТелоКакСтроку("UTF-8"));
    Данные = ПрочитатьJSON(Чтение, Ложь);
    Чтение.Закрыть();

    Возврат Данные;

КонецФункции
```

Использование по нажатию кнопки:

```bsl
Данные = ПолучитьДанныеСУстройства();

Если Данные = Неопределено Тогда
    Сообщить("Устройство не отвечает");
    Возврат;
КонецЕсли;

Если НЕ Данные.stable Тогда
    Сообщить("Масса ещё не устоялась");
    Возврат;
КонецЕсли;

Если ПустаяСтрока(Данные.weight_barcode) Тогда
    Сообщить("У товара «" + Данные.name + "» не задан номер на весах");
    Возврат;
КонецЕсли;

// Дальше — как при обычном сканировании: 1С сама найдёт товар
// и вес по весовому штрихкоду
ОбработатьШтрихкод(Данные.weight_barcode);
```

Код кладётся во внешнюю обработку или в форму чека — туда, откуда его
удобно вызвать кнопкой.

### Способ 2: только вес, без программирования

Приложение отвечает как весы Масса-К по «Протоколу 100», поэтому штатный
драйвер весов подключается к нему как к обычным весам.

Администрирование → Подключаемое оборудование → Добавить:

| Поле | Значение |
|---|---|
| Тип оборудования | Электронные весы |
| Драйвер | МАССА-К |
| Интерфейс | Ethernet (TCP/IP) |
| Адрес | тот, что показан в приложении |
| Порт | 5001 (или заданный в приложении) |

Дальше — **«Тест устройства»**. Если 1С покажет массу, связь есть.

Штрихкод так не передать: протокол умеет только массу, тару и флаги.

### Какой выбрать

**Способ 2 — для проверки.** Настроили штатный драйвер, увидели вес в 1С,
значит сеть, адрес и порт верные. Занимает минуту и ничего не требует.

**Способ 1 — для работы.** Он даёт то, ради чего всё затевалось: товар
определяется камерой и попадает в чек вместе с весом, без набора номера.

## Порядок внедрения

1. Телефон и касса в одной сети
2. В приложении: «Для 1С» → «Запустить»
3. Сверить шаблон весового штрихкода с 1С
4. Проверить связь способом 2 или скриптом:
   `python3 tools/test_device.py АДРЕС --http 8090`
5. Завести номера на весах у товаров в приложении
6. Подключить способ 1 в 1С

---

## Если не отвечает

— **устройство и касса в одной сети?** Проверить с кассы: открыть
  `http://АДРЕС:8090/` в браузере
— **приложение открыто?** Сервер работает, пока оно не закрыто
— **адрес не мобильного интернета?** Приложение показывает адрес Wi-Fi
  и предупреждает, если его нет
— **порт не занят?** Приложение напишет об этом в журнале на экране «Для 1С»

На экране «Для 1С» есть журнал обращений: если запрос от 1С дошёл,
он там появится. Это самый быстрый способ понять, доходит ли вообще.
